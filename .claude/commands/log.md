현재 세션의 작업 내용을 `log/` 디렉토리에 기록한다.
선택 인자 `$ARGUMENTS`가 있으면 세션 목표 설명에 활용한다.

반드시 아래 단계를 순서대로 완전히 이행한다.

---

## Step 1 — 이전 로그 파악

```bash
ls log/
```

가장 최근 로그 파일을 Read 툴로 열어 형식과 PR 이력, 미완료 항목을 파악한다.

---

## Step 2 — 이번 세션 작업 파악

다음 정보를 수집한다:

```bash
# 이번 세션에서 생성된 커밋 확인
git log --oneline main..HEAD 2>/dev/null || git log --oneline -20

# 변경된 파일 목록
git diff main..HEAD --stat 2>/dev/null || git diff --stat HEAD~5..HEAD

# 최근 PR 이력
gh pr list --state merged --limit 5
```

---

## Step 3 — 로그 파일 작성

파일명 형식: `log/YYYY-MM-DD-session-NN.md`
- 날짜는 오늘 날짜 (`currentDate` 컨텍스트 참조)
- 세션 번호는 기존 로그 파일 개수 + 1

**반드시 아래 섹션을 모두 포함한다:**

```markdown
# 작업 로그 — YYYY-MM-DD 세션 NN

> 세션 목표: (이번 세션에서 하려 했던 것)

---

## 작업 요약

| #   | 작업 | 소요 시간 |
| --- | ---- | --------- |
| 1   | ...  | ~N분      |

---

## 사용자 요청 흐름

1. **"사용자 메시지 요약"**
   → 어떻게 대응했는지, 어떤 결정을 내렸는지

---

## 주요 결정 및 트레이드오프

### 결정 제목

| 방향 | 장점 | 단점 |
| ---- | ---- | ---- |
| 옵션 A | ... | ... |
| **선택한 옵션** ✅ | ... | ... |

→ 선택 이유 한 줄 요약.

---

## 생성/수정 파일 목록

\`\`\`
새로 생성:
  경로/파일명   (용도 한 줄)

수정:
  경로/파일명   (변경 내용 한 줄)

삭제:
  경로/파일명   (이유)
\`\`\`

---

## 오류 수정 이력

### 카테고리명

| 오류 | 원인 | 수정 |
| ---- | ---- | ---- |
| 오류 메시지 요약 | 원인 | 해결 방법 |

(오류가 없었으면 섹션 생략)

---

## 과제 스펙 문서화 및 프로세스 정비

| 작업 | 내용 |
| ---- | ---- |
| ... | ... |

(해당 작업이 없으면 섹션 생략)

---

## PR 이력

| PR  | 브랜치 | 내용 |
| --- | ------ | ---- |
| #N  | `브랜치명` | 한 줄 설명 |

---

## 다음 세션에서 할 일

- [ ] 미완료 항목 (이전 세션에서 넘어온 것 포함)
- [ ] 새로 파악된 할 일
```

### 작성 규칙

- 이전 세션 로그의 미완료 항목(`- [ ]`)은 이번 세션 로그의 "다음 세션에서 할 일"로 옮겨 기록한다.
- 이번 세션에서 완료된 항목은 이전 세션 로그에서 `- [x]`로 업데이트한다.
- 디자인 수정의 세부 내역은 생략하고 어떤 기능/영역을 작업했는지 위주로 기록한다.
- 소요 시간은 대략적으로 추정한다.

---

## Step 4 — 이전 로그 미완료 항목 업데이트

이번 세션에서 완료한 항목이 이전 로그에 `- [ ]`로 남아 있으면 `- [x]`로 업데이트한다.

---

## Step 5 — 완료 보고

작성된 로그 파일 경로를 보고한다.
