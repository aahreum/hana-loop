## 주요 결정 및 트레이드오프

### 1. 날짜 필터 — Popover vs 이전 Dialog 분기

| 방향                                           | 장점                              | 단점                                        |
| ---------------------------------------------- | --------------------------------- | ------------------------------------------- |
| 데스크탑 inline + 모바일 Dialog (이전)         | 모바일에서 풀폭 사용              | 두 분기 유지 비용, preset 추가가 어색       |
| **단일 Popover 통일** ✅                        | 한 컴포넌트로 모든 viewport 대응. preset + From/To 한 위치 | 모바일 좁은 viewport 에서 popover 폭 ~280px |

→ Radix Popover 가 모바일에서도 viewport 안에 자동 배치. preset 추가가 자연스럽고 시각적 일관성 ↑.

### 2. 카드 뷰 정렬 — 위치와 통합

| 방향                                  | 장점                              | 단점                                            |
| ------------------------------------- | --------------------------------- | ----------------------------------------------- |
| 카드별 정렬 핸들                       | 직관성                             | UI 복잡, 상태 관리 어려움                        |
| **상단 Select + 방향 토글 버튼** ✅    | 모바일 패턴 친화 + 단일 진입점     | 데스크탑 컬럼 클릭과 별개 UI (hook 으로 상태만 통일) |

→ `useActivitySort` 로 view-state 분리해 두 뷰가 동일 sortKey/sortDir 공유. UI 만 분기.

### 3. 동적 기간 범위 — 별도 API vs 응답에서 추출

| 방향                              | 장점                                  | 단점                                            |
| --------------------------------- | ------------------------------------- | ----------------------------------------------- |
| `/api/emissions/range` 신규       | 명확한 책임 분리                      | round-trip 추가 + jitter 영향 → 첫 LCP 늦어짐    |
| **응답에서 reduce 로 추출** ✅     | 추가 비용 0. 데이터셋 변경 시 자동 반영 | useDashboard 안에 작은 reduce 로직 1개 추가     |

→ 데이터셋 8개월 × 수십 행 규모라 reduce 비용 무시. RSC prefetch + 클라 hydrate 후 즉시 사용 가능.

### 4. queryKey 매칭 — 빈 문자열 vs undefined

| 방향                                  | 장점                              | 단점                                |
| ------------------------------------- | --------------------------------- | ----------------------------------- |
| store 의 from/to 를 `null` 타입       | 명확                              | 타입 변경 + 다른 호출부 영향        |
| **빈 문자열로 두고 hook 에서 `undefined` 로 정규화** ✅ | 타입 변경 없음, 호환 유지        | 빈 문자열 == "필터 없음" 약속 명문화 필요 |

→ `useEmissionResults` 안에서 `params?.from || undefined` 변환. RSC prefetch (from/to 미전달) 와 클라 (빈 문자열 → undefined) 가 동일 queryKey 생성 → hydrate 정상.
