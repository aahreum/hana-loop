## 주요 결정 및 트레이드오프

### 모바일 헤더 날짜 트리거 — 두 줄 깨짐 해결

| 방향                                 | 장점                              | 단점                                      |
| ------------------------------------ | --------------------------------- | ----------------------------------------- |
| 트리거 폰트 줄이기                   | 변경 최소                         | 데스크톱과 일관성 깨짐, 가독성 ↓          |
| 헤더에서 트리거 외 요소 축약        | 다른 요소(테마 토글)도 영향        | 다른 영역 부작용 큼                       |
| **모바일 라벨만 "기간" 축약** ✅    | 헤더 한 줄 보장. 트레이드오프는 트리거에 현재 선택 안 보이는 점인데 popover 내부에 노출해 해소 | popover 내부 한 박스 추가 필요 |

→ 가장 작은 surface 변경으로 시각 깨짐 해결.

### ActivityForm date input 모바일 텍스트 잘림 (`2026. 05. (`)

| 방향                                                                 | 장점                                          | 단점                                                  |
| -------------------------------------------------------------------- | --------------------------------------------- | ----------------------------------------------------- |
| `pr-10` → `pr-9` + 폰트 축소                                         | 한 줄 변경                                    | 1~2자 더 들어갈 뿐 본질 미해결, 폰트만 망가짐         |
| native date 버리고 `react-day-picker` 도입                           | 텍스트 직접 그리므로 `text-overflow: ellipsis` 정상 동작. 모든 폭에서 완벽 | 라이브러리 +30KB, shadcn Calendar 추가 작업 1~2h      |
| **`grid-cols-2` → `grid-cols-1 sm:grid-cols-2`** ✅                  | 한 줄 변경. 모바일에선 풀폭 확보 → 잘림 사라짐 | sm 이상에선 기존 2단 유지. 다른 칸(활동 유형)도 1단으로 같이 떨어지는데 모바일 가독성 측면 ↑ |

→ 가장 작은 변경 + 본질 해결. react-day-picker 도입은 잔여 폭 부족 시 옵션으로 보류.

### `react-day-picker` 사용 가능 여부 검토

| 검토 항목 | 결론 |
| --------- | ---- |
| 과제 스펙 명시 | "MUI / Ant Design 같은 무거운 UI 라이브러리 금지", "shadcn/ui, headless UI 같은 경량 유틸 허용" |
| 성격 | 단일 목적 (캘린더만), 30KB gzipped, 스타일은 사용자가 입힘 |
| shadcn 의존성 | shadcn/ui 의 공식 `Calendar` 컴포넌트 내부 의존 |
| **결론** | ✅ 명시적 허용 범위. 도입 시 발표 trade-off 표 한 줄 추가 권장 |

### GIF 압축 도구 선택

| 도구 | 결과 (dashboard 5.0M 기준) | 메모 |
