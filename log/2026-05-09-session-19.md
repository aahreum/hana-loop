## 사용자 요청 흐름

1. **"날짜 키보드로 입력 못하게 아예 막고싶어 어떻게 해야해? 그냥 선택만 하게"**
   → `onKeyDown={(e) => e.preventDefault()}` 로 차단 시도. Tab 키만 통과시켜 포커스 이동 유지.

2. **"입력 가능하게 하되 yyyy.mm 구조에 맞게 입력하도록 제한은 못하나? 입력을 못하게 막으니까 좀 많이 어색"**
   → `onChange` 단에서 `^\d{4}-(0[1-9]|1[0-2])$` 정규식으로 형식 거부 + 범위 밖이면 setter 미호출(controlled input 자동 복원).

3. **"범위 검증을 4자입력 하면 연도, 2자 입력하면 월로 끊어줘 그리고 정상값 범주로 넘어가면 지금 연도 월로 맞춰줘"**
   → 형식 거부 → 범위 밖이면 minDate/maxDate 로 자동 clamp 로 변경. 단, native month input 의 onChange 발화 타이밍이 브라우저별로 달라 일부 케이스에서 의도대로 동작 안 함.

4. **"아냐 지금 동작 안해 그냥 입력 못하도록 막아줘 선택으로만 하자"**
   → 1번 안으로 회귀. `blockKeyboardInput` (Tab 외 preventDefault) 로 키 입력 자체 차단. picker UI 로만 선택.

## 주요 결정 및 트레이드오프

### 키보드 입력 처리 — 검증 vs 차단

| 방향                                   | 장점                                  | 단점                                                  |
| -------------------------------------- | ------------------------------------- | ----------------------------------------------------- |
| onChange 정규식 검증 + clamp           | 키보드 입력 자체는 자연스러움          | native month input 의 onChange 발화 타이밍이 브라우저별로 달라 일부 케이스에서 의도대로 동작 안 함 |
| **onKeyDown 으로 키 입력 자체 차단** ✅ | 100% 결정적 동작. picker 로만 선택 — 비현실적 값 원천 차단 | 키보드 직접 입력이 막혀 살짝 어색하나 picker 가 빠른 단축키 제공 |

→ 정규식 검증 방식이 동작 일관성을 보장 못해 사용자가 직접 차단 방식 선택. native month input 의 input event 동작이 형식 검증으로 다루기에는 가변적이라는 학습.
