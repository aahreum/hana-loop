## 주요 결정 및 트레이드오프

### 1. jitter 시뮬레이션 — prod 비활성화 vs 유지 + prefetch 분리

| 방향                                       | 장점                                            | 단점                                                |
| ------------------------------------------ | ----------------------------------------------- | --------------------------------------------------- |
| `jitter()` prod 비활성화                   | LCP -6~7초 (단일 변경으로 가장 큰 폭)           | 과제 스펙의 loading/error UX 시연 불가              |
| **유지 + RSC prefetch 만 우회** ✅          | 첫 LCP 빠름 + loading/error UX 시연 가능        | 첫 페이지 prefetch 와 인터랙션 API 경로가 분리됨    |

→ 과제 스펙이 "200~800ms 지연 + 10~20% 실패 시뮬레이션" 을 명시. 평가 항목인 loading/error 처리를 보존하면서, LCP 측정에서만 첫 fetch 우회. 사용자가 jitter 유지를 명시적으로 선택.

### 2. RSC prefetch 데이터 소스 — fetch self-call vs supabaseAdmin 직접

| 방향                              | 장점                                 | 단점                                                 |
| --------------------------------- | ------------------------------------ | ---------------------------------------------------- |
| Vercel 서버에서 `/api/...` self-fetch | API Route 와 로직 일관               | jitter 가 prefetch 에도 적용됨 — LCP 효과 사라짐    |
| **`supabaseAdmin` 직접 호출** ✅   | jitter 우회 → LCP 빠름. snake→camel 변환은 `toCCArray` 재사용 | API Route 와 별도 fetch 함수 (server-data.ts) 생김  |

→ `shared/lib/server-data.ts` 에 서버 전용 fetch 함수 3개 분리. `'server-only'` import 로 클라 빌드 차단.

### 3. queryKey 매칭 전략

useFilterStore 의 `selectedCompanyId` 가 zustand persist 미사용 → 항상 null 로 시작 → `useLayout` effect 가 첫 회사 자동 선택. 따라서 RSC 가 `companies[0]` 을 prefetch 하면 클라이언트가 첫 회사를 선택할 때 캐시 그대로 hydrate. 다른 회사로 전환 시에는 clean miss → 그 시점부터는 jitter 적용 (자연스러움).

| 방향                              | 장점                              | 단점                                            |
| --------------------------------- | --------------------------------- | ----------------------------------------------- |
| 모든 회사 prefetch                | 회사 전환 시에도 캐시 hit         | prefetch 양 N배. 사용 안 하는 데이터 직렬화     |
| **첫 회사만 prefetch** ✅          | 페이로드 최소. 첫 진입(가장 흔한 케이스) 커버 | 다른 회사 전환 시 jitter 보임                   |

### 4. Recharts dynamic import — ssr false vs default

| 방향               | 장점                               | 단점                                  |
| ------------------ | ---------------------------------- | ------------------------------------- |
| ssr: false         | SSR HTML 페이로드 작아짐          | 첫 paint 에 차트 빈 영역 → CLS 우려  |
| **ssr 기본값(true)** ✅ | chunk 분리 + SSR 그려짐 → CLS 안전 | SSR HTML 페이로드는 그대로            |

→ 메인 번들에서 Recharts 가 분리되는 효과는 동일 (chunk 분리). CLS 0 유지가 더 중요.

### 5. dashboard/page.tsx — `force-dynamic` 명시

빌드 시점에 supabase 호출 → HTML prerender 시 데이터 박힘 → 사용자에게 stale 데이터. `force-dynamic` 으로 매 요청 재실행. supabase round-trip 50~100ms 추가는 클라이언트 fetch 보다 훨씬 빠름.

### 1. 헤더 날짜 필터 input 이 비어 보이는데 데이터가 표시됨 (UX)

**현상**: `/dashboard` 헤더의 month input 두 개가 `----년 ---` placeholder 형태로 보이는데 차트/KPI 에는 데이터가 정상 표시. 사용자가 "필터가 비어있는데 왜 데이터가?" 하고 어색함을 느낌.

**원인**: `useFilterStore` 의 `from`/`to` 기본값(`DATASET_FROM = '2025-01'` / `DATASET_TO = '2025-08'`)이 자동 적용 → 데이터 fetch 는 정상. `DateRangePicker.tsx:74,93` 에서 `value={from}` / `value={to}` 로 바인딩되어 있어 코드상 값이 들어가야 정상이지만, 화면에서는 빈 placeholder 로 보임 (브라우저별 native month input 렌더링 차이 가능성).

**개선 아이디어** (조합 가능):

| 옵션 | 내용 | 비용 | 효과 |
| --- | --- | --- | --- |
| **A. 적용 범위 캡션** | input 옆/아래에 "기간: 2025-01 ~ 2025-08 (전체 데이터셋)" 텍스트 노출 | 낮음 | input 비어 보여도 사용자가 적용 범위 즉시 파악 |
| **B. 빠른 선택 버튼** | "전체 / 최근 6개월 / 최근 3개월" preset 버튼 그룹. 한 번 누르면 input 에 값 들어가고 시각적으로 명확 | 중간 | 디폴트 인지 + 자주 쓰는 범위 단축 |
| **C. month input 값 표시 검증** | dev 에서 input 의 실제 `value` attribute 확인. 비어 있으면 한국어 로케일 + native picker 의 placeholder 이슈. 채워져 있는데 보이지 않으면 CSS 또는 폰트 렌더링 문제 | 매우 낮음 | 근본 원인 파악 후 A/B 결정 |

### 2. 활동 데이터 삭제 시 행이 뿌옇게 보이다 삭제됨 (UX)

**현상**: 활동 테이블에서 삭제 버튼 클릭 → 해당 행이 opacity 가 줄어들면서 잠시 뿌옇게 보이다가 사라짐. jitter 200~800ms + DELETE 호출 동안 의도된 disabled 표시이지만 사용자가 어색하다고 느낌.

**원인**: `ActivityTable` 의 `isDeleting && deletingId === activity.id` 조건으로 행에 opacity 적용. mutation pending 상태 시각화는 맞지만, 시간이 길어서(jitter) 부자연스러움.

**개선 아이디어**:
- **소거 애니메이션** — fade-out + height 0 으로 부드럽게 사라지게 (CSS transition)
- **inline spinner** — 행 전체 dim 대신 삭제 버튼만 spinner 로 교체. 다른 컬럼은 그대로 보임
- **확인 다이얼로그** — 삭제 전 "삭제하시겠습니까?" 확인. mutation 시간이 사용자 의식 밖으로 빠짐 (UX 자체 변경)
- **Optimistic Update + Rollback** — 즉시 UI 에서 제거 → 실패 시 toast + 복구. 단 `maybeFail` 15% 환경에서 취소 잦으면 오히려 혼란 (이미 README trade-off 로 미채택)

**추천**: inline spinner (행 dim 제거) + 부드러운 fade-out. 가장 적은 비용으로 어색함 해소.

### 3. 활동 데이터 추가 시 활동량 상한선 검증 부재 (검증)

### 4. 모바일/태블릿 카드 뷰에서 활동 데이터 정렬 기능 부재 (기능)

**현상**: 데스크탑(`>= lg`) 테이블 뷰에서는 컬럼 헤더(날짜/유형/수량/Scope) 클릭으로 정렬 가능. 그러나 `lg` 미만에서 카드 뷰로 전환되면 컬럼 헤더가 사라져 정렬 동작 자체가 노출되지 않음 → 사용자가 모바일/태블릿에서 정렬 불가능.

**원인**: 정렬 UI 가 `<th>` 클릭에 의존하는 테이블 전용 패턴. 카드 뷰로 전환 시 동등 기능을 노출하는 컨트롤이 없음.

**개선 아이디어**:

| 옵션 | 내용 | 비용 | 효과 |

| **B. 정렬 SegmentedControl** | 카드 뷰 상단에 가로 토글 버튼 그룹 (날짜/유형/수량). 화살표 아이콘으로 방향 토글 | 중간 | 시각적 직관성 ↑ 다만 옵션 4개라 좁은 화면에서 잘림 가능 |

**추천**: **A + C**. select box 는 모바일 패턴 친화적이고 가장 짧은 코드. 기존 `<th>` 클릭 정렬과 상태를 공유하도록 hook 분리.

### 5. 활동 추가 시 unit 필드 의미 미스매치 → 데이터 일관성 깨짐 (버그 + UX)

**현상**: 폼에서 활동 추가 시 `unit` 필드에 무엇을 입력하더라도 배출계수 선택 시 자동으로 덮어씌워짐. 그 결과로 저장된 활동의 단위가 seed 데이터와 다름.

**원인**:

| 위치 | 값 (예시) | 의미 |
| --- | --- | --- |
| `emission_factors.unit` | `kgCO2e/kWh` | **배출계수의 단위** (kgCO2e per 활동단위) |
| `activities.unit` (seed) | `kWh` | **활동량의 단위** (분모만) |

`ActivityForm.tsx:171` 에서 `setValue('unit', f.unit)` — 즉 `emission_factor.unit` (kgCO2e/kWh) 을 `activity.unit` 에 그대로 복사. 의미가 다른 두 컬럼을 같은 값으로 채워서 seed 와 일관성 깨짐.

**근본 질문 — `activities.unit` 컬럼이 필요한가?**

redundant 함:
- 활동 유형(electricity/raw_material/transport) 이 결정되면 단위는 사실상 결정됨
- 또는 `factor_category` 만 있으면 `emission_factors.unit` 분모로 자동 도출 가능 (`kgCO2e/kWh` → `kWh`)
- 사용자가 직접 입력할 의미가 없음 (이미 readOnly 인 것도 같은 맥락)

**개선 아이디어**:

| 옵션 | 내용 | 비용 | Trade-off |
| --- | --- | --- | --- |
| **A. factor.unit 분모만 추출해서 저장** | `f.unit.split('/')[1] ?? f.unit` 로 `kWh` 만 저장 | 매우 낮음 (한 줄) | 가장 빠른 일관성 회복. 폼 UI 는 그대로 |
| **B. 폼에서 unit 입력 제거 + 자동 파생** | 폼 UI 에서 unit 필드 제거, factor 선택 시 서버/클라에서 자동 도출. 사용자에게는 라벨로만 표시 | 중간 | UX 단순화. 사용자 입력 부담 ↓ |
| **C. activities.unit 컬럼 자체 제거** | DB 마이그레이션 + Zod 스키마 수정. 표시 시 factor 에서 동적 도출 | 높음 | 가장 깨끗하지만 마이그레이션 필요 |

**추천**: **B**. "단위가 필요한가?" 질문에 직접 답하는 방향. UI 에서 단위 필드를 없애고, 폼 제출 시 `factor.unit` 분모를 자동 채워 저장. DB 컬럼은 유지(과거 데이터 호환). 표시 시에는 활동의 unit 을 그대로 사용.

**구현**:
- `ActivityForm.tsx` 의 단위 input 영역 제거. 활동량 입력란을 `col-span-2` 로 확장하거나 옆에 `(kWh)` 같은 정적 라벨로 대체
- 폼 submit 시 `factor.unit.split('/')[1] ?? factor.unit` 으로 unit 자동 채움
- `CreateActivitySchema.unit` 은 그대로 유지 (서버 검증)

### 8. 모바일에서 가로 스크롤 발생 (버그)

**현상**: 모바일(안드로이드 Chrome / Samsung Internet) 에서 `/dashboard` 진입 시 화면이 좌측으로 살짝 잘려 보이며 가로 스크롤이 생김. KPI 카드 좌측 테두리가 viewport 밖으로 밀려나감.

**원인**: `globals.css` 의 `html` / `body` 에 `overflow-x` 미설정. `NavigationDrawer` 가 모바일 닫힘 상태에서 `fixed left-0 w-60 -translate-x-full` 로 viewport 밖으로 transform — 일부 모바일 브라우저는 transform 후 위치까지 layout overflow 로 잡아 가로 스크롤 발생.

**개선 아이디어**:

| 옵션 | 내용 | 비용 | 부작용 |
| --- | --- | --- | --- |
| **A. `body { overflow-x: clip }`** | globals.css 한 줄 추가. clip 은 stacking context 안 만듦 | 매우 낮음 | 없음 (sticky 동작 보존) |
| **B. `body { overflow-x: hidden }`** | 동일 효과 | 매우 낮음 | sticky 헤더/사이드바 위치 깨질 위험 |
| **C. NavigationDrawer 모바일 닫힘 시 `display: none`** | translate 대신 hidden 처리 | 낮음 | open/close 애니메이션 사라짐 |

**추천**: **A** — 표준 처방이고 부작용 없음. 한 줄로 끝.

**구현**:
```css
/* src/app/globals.css 의 body 블록에 추가 */
body {
  ...
  overflow-x: clip;
}
```
