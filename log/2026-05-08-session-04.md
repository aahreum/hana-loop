## 사용자 요청 흐름

1. **다크모드/라이트모드 토글 구현**
   → 브라우저 시스템 설정을 기본값으로 사용하고, 사용자가 서비스에서 직접 설정하면 localStorage에 저장해 우선 적용. Zustand persist 미들웨어로 구현. CSS는 이미 `:root.dark`, `:root.light`, `@media prefers-color-scheme` 세 케이스가 준비되어 있어 JS는 `<html>` class만 제어.

2. **Hydration 에러 발생**
   → 서버: `typeof window === 'undefined'` → `'light'` fallback → Moon 렌더. 클라이언트: 시스템 다크모드 감지 → `'dark'` → Sun 렌더. `mounted` state 패턴으로 hydration 전엔 항상 Moon을 렌더링해 SSR과 일치시킴.

3. **다크모드 사이드바 그린톤 수정**
   → `:root.dark`의 `--sidebar-bg: #022c22` (에메랄드 그린)이 라이트모드와 달라 보이는 문제. 라이트모드와 동일한 네이비 `#0d1b3e` / `#1a2c5c`로 교체. 시스템 다크모드 폴백(`@media` 블록)도 동일하게 적용.

4. **다크모드 hover 과함**
   → ghost button의 `hover:bg-accent`가 다크모드에서 `--accent: #eff6ff` (밝은 파란색)으로 나타나는 문제. `--accent: var(--gray-200) = #1e293b`로 교체.

5. **파비콘 생성**
   → 브랜드 그라디언트 라운드 사각형 + 흰색 H 글자. Next.js App Router는 `src/app/icon.svg`를 자동으로 favicon으로 사용. H 글자는 텍스트 대신 rect 3개(좌/우 세로바 + 가로바)로 그려 렌더링 일관성 확보.

6. **docs 업데이트**
   → `docs/05-design-system.md`: 컬러 팔레트 실제 구현 반영, 다크모드 동작 방식 섹션 추가, NavigationDrawer 설명 수정. `docs/01-architecture.md`: uiStore 설명에 theme persist 추가, shared/hooks에 useTheme 추가.

## 주요 결정 및 트레이드오프

### 테마 상태 설계

| 방향 | 장점 | 단점 |
| --- | --- | --- |
| `'light' \| 'dark'` (명시값만) | 단순 | 시스템 설정 변경 감지 불가 |
| **`'light' \| 'dark' \| null` (null=시스템)** ✅ | 시스템 설정 존중, persist 시 null은 저장 안 해도 됨 | 약간 복잡 |

→ null이면 CSS `@media` 폴백이 처리하므로 JS에서 시스템 미디어쿼리를 구독할 필요 없음.

### Hydration mismatch 해결 방식

| 방향 | 장점 | 단점 |
| --- | --- | --- |
| `suppressHydrationWarning` | 즉시 적용 | 에러 숨기는 방식, 근본 해결 아님 |
| **`mounted` state** ✅ | SSR-safe, 표준 패턴 | 첫 렌더 후 아이콘 교체 (체감 불가) |

→ Next.js 공식 권장 패턴. hydration 전엔 서버와 동일한 Moon을 유지.

### 파비콘 형식

| 방향 | 장점 | 단점 |
| --- | --- | --- |
| `favicon.ico` (바이너리) | 레거시 브라우저 지원 | 생성 도구 필요, 크기 고정 |
| **`icon.svg` (App Router)** ✅ | 벡터, 모든 해상도 대응, Next.js 자동 등록 | IE 미지원 (프로젝트 무관) |

→ Next.js App Router 권장 방식. `src/app/icon.svg` 위치에 두면 자동으로 `<link rel="icon">` 주입.
