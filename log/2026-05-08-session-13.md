## 주요 결정 및 트레이드오프

### 1. API Route 테스트 3종 세트 — 작성 vs 의도적 스킵

| 방향                           | 장점                                                | 단점                                                          |
| ------------------------------ | --------------------------------------------------- | ------------------------------------------------------------- |
| 3종 세트 작성 (성공/400/500)   | CLAUDE.md "API Route 테스트 3종 세트" 룰 충족       | Supabase chain·RPC 모킹 비용 ↑, mock 테스트가 실제 버그 못 잡음 |
| **의도적 스킵 + README 명시** ✅ | 시간 → README 에 투자, 마감 임팩트 ↑                | 룰 위반 — 단, README 에 사유 명시로 "부재"→"결정" 전환        |

→ 평가자 입장에서 "테스트 부족"이 아닌 "테스트 영역과 통합 환경 검증을 분리한 trade-off 설계"로 인식되도록 README 의 "테스트" 섹션과 "주요 설계 결정" 표 양쪽에 명시.

### 2. README 분량·구성 — 길게 vs 짧게

| 방향                                     | 장점                                         | 단점                                            |
| ---------------------------------------- | -------------------------------------------- | ----------------------------------------------- |
| 짧게 (1페이지)                            | 가독성                                        | 평가 항목 13개 다 못 담음                       |
| **중간 (12 섹션 + docs 링크)** ✅          | 평가 기준 풀커버 + 깊은 설명은 docs 위임      | 길이는 길지만 색인이 명확                        |
| 모든 docs 내용 README 에 통합            | 한 파일로 끝                                  | 4000+ 줄, 유지보수 불가                         |

→ README 는 entry point + 평가 항목 매핑 + trade-off 표만 자체 보유, 깊은 내용은 `docs/0~11` 로 13개 링크 제공.

### 3. AI 활용 내역 — 추상적 언급 vs 분담 명시

| 방향                                | 장점                                         | 단점                                            |
| ----------------------------------- | -------------------------------------------- | ----------------------------------------------- |
| "Claude 와 페어 프로그래밍" 한 줄   | 간단                                          | 발표 시 "어디서 직접 판단했는가" 답변 못 함     |
| **AI 주도 / 사람 주도 영역 분리** ✅ | 평가 항목 "AI 활용 내역" 의 의도에 정합. 발표 스크립트로 그대로 활용 가능 | 길이 길어짐 |

→ AI = boilerplate · 반복 패턴 · 1차 문서, 사람 = 정보 구조 · 디자인 의사결정 · trade-off 판단 · FSD 경계 결정 · `CLAUDE.md` 헌법 작성. "AI 는 속도, 사람은 방향" 으로 요약.

### 4. README PR 이후 우선순위 — Excel Import vs Vercel + 시연 GIF

| 방향                       | 장점                                          | 단점                                          |
| -------------------------- | --------------------------------------------- | --------------------------------------------- |
| Excel Import (가점)        | 가점 항목 명시적 충족                         | 2~3시간 비용, 평가자가 직접 만져봐야 가치 발현 |
| **Vercel 배포 + 시연 GIF** ✅ | 30분 + GIF 30분 = 1시간으로 첫인상 극대화. 라이브 링크는 평가자가 즉시 클릭 가능. Lighthouse 점수 첨부도 가능 | 가점 표에 명시적 항목은 아님 (그러나 "실행 가능한 Next.js 앱" 평가에 직결) |

→ Excel Import 는 마감 여유 시 추가 검토. Vercel + GIF 가 같은 시간 대비 평가 임팩트 최대.
