## 주요 결정 및 트레이드오프

### 모바일 날짜 인풋 — 캘린더 아이콘 + 바텀시트

| 방향                          | 장점                                | 단점                                 |
| ----------------------------- | ----------------------------------- | ------------------------------------ |
| 모바일에서 인라인 input × 2    | 구현 단순                           | 헤더가 두 줄로 깨짐 (작은 폭)        |
| **캘린더 아이콘 + 바텀시트** ✅ | 헤더 컴팩트, 모바일 OS 풍 UX        | Dialog 위치 className 오버라이드 필요 |

→ shadcn `Dialog` className으로 `bottom-0 / top-auto / translate-x/y-0 / max-w-full`. `tailwindcss-animate` 미사용이라 슬라이드 애니메이션은 적용되지 않지만 zoom 애니메이션이 자연스럽게 대체.

### 카드 컴포넌트 추출 위치 — `features/dashboard/ui` vs `shared/ui`

| 방향                                | 장점                                  | 단점                              |
| ----------------------------------- | ------------------------------------- | --------------------------------- |
| `features/dashboard/ui/ActivityCard` | dashboard 슬라이스 응집               | features/A → features/B 금지 위반 |
| **`shared/ui/activity-card.tsx`** ✅ | dashboard·activities 양쪽에서 import OK | shared/ui에 도메인 컴포넌트 1개 추가 |

→ FSD 의존성 방향(`features/A → features/B` 금지) 때문에 공통 컴포넌트는 `shared/ui`. 도메인 의존(`ActivityData`, `ACTIVITY_TYPE_LABELS`)은 모두 `shared`에 있어 자연스럽게 위치.

### 사이드바 접힘 — width 0 vs icon-only

| 방향                          | 장점                              | 단점                                 |
| ----------------------------- | --------------------------------- | ------------------------------------ |
| **width 0 (`lg:hidden`)** ✅ | 본문 영역 최대 활용, 구현 단순     | 메뉴 접근에 클릭 한 번 더             |
| icon-only (~56px)             | 메뉴 즉시 식별                    | 디자인 토큰/메뉴 아이콘 라벨 추가 필요 |

→ 과제 제출에는 width 0이 충분. icon-only는 추후 사용자 피드백 후 재검토.

### 배출계수 데이터 정합성 — 4개로 완전 축소

| 방향                          | 장점                                       | 단점                                  |
| ----------------------------- | ------------------------------------------ | ------------------------------------- |
| 6개 유지 (fuel/waste 포함)    | UI 다양성, Scope 1 시각화                  | 과제 스펙(4개) 외 임의 데이터, 출처 가짜 |
| **4개로 완전 축소** ✅         | 과제 스펙 100% 충실, 정직                  | Scope 1 시각화 없음 (전기=2, 원자재=3, 운송=3) |
| 6개 유지 + 출처 라벨만 정직   | 절충안                                     | enum/UI 5개 유지, 정합성 절반          |

→ 과제 출처(Image #9)에 4개만 있고 나머지(`fuel_diesel`, `waste_general`)는 임의 추가했음을 사용자에게 솔직히 보고. "4개로 완전 축소" 선택.

### 출처 라벨 정직화

기존 라벨(`한국 환경부 2023`, `Ecoinvent 3.9`, `IPCC 2021`, `국토부 2023`, `환경부 폐기물통계 2023`)은 그럴듯하지만 검증 안 된 작명. 모두 `'GHG Protocol 계수'`로 통일 — 실제 GHG Protocol 표준 계수에서 통용되는 값임을 표기.

### DB enum 변경 처리 — initial migration 직접 수정 vs 새 마이그레이션

| 방향                                | 장점                              | 단점                                  |
| ----------------------------------- | --------------------------------- | ------------------------------------- |
| **initial_schema.sql 수정** ✅     | 단순, 다음 `db reset`으로 자동 반영 | 이미 원격 적용 시 동기화 별도 필요    |
| `ALTER TYPE` 새 마이그레이션 작성   | 원격 점진 마이그레이션에 안전     | Postgres enum value 제거는 복잡 (재생성 필요) |

→ 과제 프로젝트 → 로컬 `supabase db reset`으로 충분. 원격 적용 시점에는 새 마이그레이션 필요.

## 모바일 카드 레이아웃 (공통)

```
┌──────────────────────────────────────┐
│ [유형] 설명/이름           [Scope]   │  ← 1줄: 유형 + 메인 텍스트 / Scope (우측)
│ 메타1                       메타2     │  ← 2줄: 부 메타 정보 좌·우 분할
│ 메타3                       메타4     │  ← 3줄: 추가 메타 (muted, 작은 글씨)
└──────────────────────────────────────┘
                                     [🗑] ← 휴지통은 onDelete 있을 때 카드 우측 vertical center
```

| 페이지                | 1줄                  | 2줄                  | 3줄                          | 휴지통 |
| --------------------- | -------------------- | -------------------- | ---------------------------- | ------ |
| 대시보드 최근 활동    | [유형] 설명 / Scope | 날짜 / 수량          | 배출계수: 카테고리코드        | ❌      |
| 활동 페이지 (`/activities`) | [유형] 설명 / Scope | 날짜 / 수량          | 배출계수: 카테고리코드        | ✅      |
| 배출계수 페이지 (`/factors`) | [유형] 이름 / Scope | 계수+단위 / 유효기간 | 카테고리코드 / 출처          | ❌      |
