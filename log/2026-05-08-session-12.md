## 주요 결정 및 트레이드오프

### 1. Swagger UI 렌더링 방식 — 'use client' 직결 vs dynamic ssr:false

| 방향                           | 장점                              | 단점                                  |
| ------------------------------ | --------------------------------- | ------------------------------------- |
| `'use client'` page            | 단순                              | CLAUDE.md "page는 서버 컴포넌트" 위반 |
| **container를 dynamic ssr:false** ✅ | page는 서버 컴포넌트 유지, swagger-ui-react 의 브라우저 의존성 안전 처리 | container 1단계 추가 |
| `iframe` 으로 별도 호스트       | SSR 회피                           | 다크모드/스타일 동기화 비용           |

→ react-coding-conventions의 page = 서버 컴포넌트 규칙 준수. swagger-ui-react는 DOM API에 의존하므로 SSR 시 BAILOUT_TO_CLIENT_SIDE_RENDERING이 정상 fallback이지만, dynamic ssr:false 로 명시해 의도를 코드에 남김.

### 2. OpenAPI 등록 위치 — 스키마 파일 분산 vs 단일 진입점

| 방향                                        | 장점                              | 단점                                   |
| ------------------------------------------- | --------------------------------- | -------------------------------------- |
| 각 `shared/types/*.ts` 에서 `.openapi()` 호출 | 도메인 응집                       | `extendZodWithOpenApi(z)` 호출 시점 강결합, 테스트/번들 부담 |
| **`shared/lib/openapi.ts` 한곳에서 register** ✅ | 타입 파일은 순수 Zod 유지, 메타데이터는 OpenAPI 진입점 1곳 | 스키마-엔드포인트가 분리됨            |

→ Zod 스키마는 폼 검증/응답 타입 추론이 본업이고, OpenAPI 메타데이터는 부가물. 한 파일(`shared/lib/openapi.ts`)에서 `extendZodWithOpenApi(z)` + `registry.register()` + `registerPath()` 모두 처리.

### 3. `/api/docs` 응답 — 동적 vs 정적

| 방향              | 장점                  | 단점                            |
| ----------------- | --------------------- | ------------------------------- |
| 매 요청 generate  | 변경 즉시 반영        | 매번 generate 비용              |
| **`force-static`** ✅ | 빌드 시 1회 생성      | 스키마 바뀌면 재빌드 필요       |

→ 스펙은 빌드 산출물의 일부로 처리. 빌드 결과에서도 `○ /api/docs` 정적 prerender로 확인됨.

### 4. yearMonth 검증 — 분산 vs 단일 출처

| 방향                                | 장점                              | 단점                                   |
| ----------------------------------- | --------------------------------- | -------------------------------------- |
| 각 스키마에서 `regex(/^\d{4}-\d{2}$/)` | 작성 즉시            | 12군데 중복, 월 범위 검증 부재 (`2026-99` 통과) |
| **`shared/types/common.ts` 의 `YearMonthSchema`** ✅ | 단일 출처, 월 01-12 강제 | 메시지 변경 시 일괄 영향              |

→ Gemini 지적 반영. `^\d{4}-(0[1-9]|1[0-2])$` 로 강화하면서 메시지(`'YYYY-MM 형식이어야 합니다'`)는 유지해 기존 테스트(`post.test.ts`) 호환.

### 5. `/docs` 와 대시보드 영역 분리 — Route Group `(app)`

| 방향                            | 장점                        | 단점                                          |
| ------------------------------- | --------------------------- | --------------------------------------------- |
| AppShell 내부 pathname 분기     | 변경량 작음                 | widgets 가 라우팅 분기 책임을 갖게 됨         |
| `target="_blank"` 새 탭         | 1줄 변경                    | 새 탭에서도 같은 root layout — 시각 충돌 동일 |
| **Route Group `(app)`**  ✅    | Next.js 표준, 책임 분리 명확 | 페이지 4개 이동 + ThemeApplier 분리 비용     |

→ swagger-ui-react 의 라이트 테마 강제 의존성과 다크 사이드바가 충돌. AppShell 을 `(app)/layout` 으로 옮기고 `/docs` 는 자체 미니 헤더 layout 만 보유. `<html>` dark/light 동기화는 `ThemeApplier` 로 분리해 root 에서 항상 mount.

### Tailwind 토큰 오타

### Lint --fix 자동 반영

prettier 포맷 규칙 8건은 `pnpm lint --fix` 로 일괄 정리.

### `.next` 빌드 캐시 깨짐

| 오류                                              | 원인                                                                        | 수정                          |
| ------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------- |
| `Cannot find module './489.js'` (`pages/_document.js` require stack) | `pnpm build` 직후 `pnpm dev` 전환 시 webpack chunk ID 재할당, App Router 프로젝트인데 `.next/server/pages/_document.js` 잔재 | `rm -rf .next` 후 dev 재시작 |

### Build 중 dev 충돌

빌드 중 dev 가 떠 있으면 `Cannot find module for page: /...` 에러. **dev 종료 → `.next` 삭제 → build** 순서 준수.

### commitlint subject-case

`Swagger UI`, `swagger UI` 같은 대문자 시작 subject 가 `subject must not be sentence-case` 로 거부됨. 한글은 통과하나 영문 토큰은 lowercase 시작 필수.

### commitlint body-max-line-length

body 줄당 100자 초과 시 거부. 긴 설명은 줄바꿈으로 분리.
