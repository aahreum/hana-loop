## 주요 결정 및 트레이드오프

### 가점 기능(Excel Import) 진행 vs 완성도 향상

| 방향                              | 장점                                            | 단점                                              |
| --------------------------------- | ----------------------------------------------- | ------------------------------------------------- |
| Excel Import 견고 버전 (4~5h)     | 가점 + 발표 데모 임팩트 ↑                       | 마감 임박 — 미완 위험. 새 코드면 회귀 리스크      |
| Excel Import 단순 (1.5h)          | 가점은 일부 확보                                | 깊이 부족 — 평가 인상 미미                         |
| **현재 구현 완성도 향상** ✅      | 채점자 진입 장벽 제거 + 첫인상 개선. 회귀 0    | 가점 항목은 추가 안 됨                            |

→ 마감 압박 + 현재 구현이 이미 풍부한 상황이라 새 기능 도입의 회귀 리스크보다 채점자 평가 흐름 매끄럽게 만드는 ROI 가 큼.

### README 평가용 키 안내 방식

| 방향                                                | 장점                            | 단점                                              |
| --------------------------------------------------- | ------------------------------- | ------------------------------------------------- |
| Supabase 키 README 직접 공개                        | 채점자 즉시 사용 가능           | service_role 키 노출 — 보안 위험 ❌               |
| 평가용 read-only anon 키 새로 발급해 README 노출    | 보안 + 즉시 사용                | 새 키 발급 + 권한 분리 설정 비용                  |
| **(채택) 직접 셋업 안내 + Vercel 데모 강조** ✅    | 보안 ↑, Vercel 데모 가 메인 평가 경로. 자체 셋업 가능자에겐 docs/08 안내 | 채점자가 로컬 직접 띄우려면 자체 Supabase 필요    |

→ Vercel 라이브 데모가 README 최상단에 있어 평가의 1차 경로는 그쪽. 로컬 실행은 자체 셋업 안내로 커버.

### README 톤 일관성 — 명사형 종결 vs 존댓말

| 방향                                       | 장점                          | 단점                                              |
| ------------------------------------------ | ----------------------------- | ------------------------------------------------- |
| 명사형 종결 유지 (기술 명세 톤)            | 간결, 발표 자료 느낌          | 사용자 안내 문서로서 톤 일관성 ↓                  |
| **모두 존댓말 통일** ✅                    | 사용자 안내 문서 톤 일관      | 일부 짧은 라벨이 길어짐 (FSD 금지 규칙 등)        |

→ README 는 채점자 대상 안내 문서이므로 존댓말 일관이 더 적합. 표·코드 블록·캡션은 가독성 위해 명사 나열 유지.
