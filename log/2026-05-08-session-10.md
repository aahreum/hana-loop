4. **React #418 hydration**
   → production minified 트레이스 분석. 브라우저 확장 또는 빌드 캐시 미스매치 가능성. 시크릿 창 / dev 모드 재현 안내.
5. **"캘린더 아이콘 cursor-pointer / 인터랙티브 전수조사"**
   → `::-webkit-calendar-picker-indicator` 는 pseudo-element 라 globals.css 전역 처리. shadcn `Label` baseline + DateRangePicker 모바일 visible label / 회사 select label / 모바일 오버레이 div 에 cursor-pointer.
6. **"삭제 버튼 hover 통일 / ChevronDown 정렬"**
   → Button cva 에 `iconSm` size (h-8 w-8) 신설. trash 버튼은 `iconSm` + ghost 기본 hover. 회사 select 의 ChevronDown 은 outer `relative` 가 label+select 둘 다 감싸 `top-1/2` 가 어긋났던 게 원인 — relative scope 를 select 에만 한정.
7. **"사이드바 닫기 툴팁 z-index 꼬임"**
   → 사이드바의 stacking context 에 잡혀 본문 영역에 가려지던 문제. `TooltipPrimitive.Portal` 로 `document.body` 직속 렌더 → 어떤 부모와도 독립.
8. **"바텀시트 input 정렬 / * primary / 액션 버튼 풀폭 2열"**
   → `mobileInputClass` 의 `h-auto` 가 Input default `h-10` 을 무력화하던 것을 정리. `*` 를 별도 span 으로 분리해 `text-primary`. 액션 버튼은 모바일 풀폭 2열 + lg 이상 우측 정렬 (sticky 제거).
9. **"날짜 아이콘 우측 정렬 / 어떻게 넣고 있어?"**
   → 답: 브라우저 native `::-webkit-calendar-picker-indicator`. Chrome shadow DOM 의 layout 을 우리 CSS 가 제어 못 해 `flex:1` 도 효과 없음. native indicator 를 시각적으로 숨기고 Lucide `<Calendar>` overlay 로 우측 직접 배치하는 패턴으로 전환.
10. **"클릭하면 picker 가 안 떠"**
    → `display:none` 이 클릭 트리거 자체를 막은 게 원인. `position:absolute + inset:0 + opacity:0` 로 indicator 를 input 전체를 덮는 투명 click 영역으로 보존. 시각적 아이콘은 overlay, 클릭 동작은 native indicator 가 받음.
11. **"docs 반영 + /log /ship"**
    → 05-design-system / react-coding-conventions 동기화 후 /log 진행.

## 주요 결정 및 트레이드오프

### 차트 카테고리 색상 — 런타임 분기 vs CSS 변수

| 방향                                | 장점                                              | 단점                                |
| ----------------------------------- | ------------------------------------------------- | ----------------------------------- |
| `useTheme()` 로 런타임에 hex 분기   | 명시적                                            | SSR 시점 mismatch 위험, 코드 분기 |
| **CSS 변수 (`--chart-cat-*`)** ✅   | SSR 안전, 다른 디자인 토큰과 일관, Recharts SVG fill 에 `var()` 자동 resolve | 라이트/다크 두 곳 정의 필요         |

→ 프로젝트 컬러 시스템과 일관. SVG fill 속성에 `var(--chart-cat-electricity)` 같이 그대로 넘기면 브라우저가 mode 별로 자동 해석.

### 캘린더 picker UX — native indicator 유지 vs overlay 전환

| 방향                                  | 장점                                       | 단점                                                 |
| ------------------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| native indicator + CSS 위치 조정      | 호출부 수정 없음                           | Chrome shadow DOM layout 제어 불안정, 위치 변동 큼  |
| **native 숨김 + Lucide Calendar overlay** ✅ | 위치/스타일 100% 제어, 다크모드 일관, 호출부 패턴 단순 | input 마다 wrapper `<div className="relative">` 필요 |

→ Chrome shadow DOM 의 `::-webkit-datetime-edit` / `::-webkit-calendar-picker-indicator` 는 `flex:1`, `margin-left:auto`, `position:absolute` 등 어떤 시도도 안정적이지 않음. native indicator 를 `opacity:0 + position:absolute + inset:0` 로 input 전체를 덮는 투명 click 영역으로 만들고, 시각 아이콘은 우리 코드로 그리는 게 가장 안정.

### shadcn cursor-pointer — 호출부 매번 vs base 클래스 한 번

| 방향                            | 장점                            | 단점                                  |
| ------------------------------- | ------------------------------- | ------------------------------------- |
| 호출부에서 매번 `cursor-pointer` | shadcn 원본 무수정 원칙 유지   | 누락 빈번, 일관성 깨짐                |
| **shadcn base class 에 baseline** ✅ | 모든 호출부 자동 적용, 일관 | shadcn 원본을 살짝 수정 (단 1줄)      |

→ 누락이 반복적으로 발생해 baseline 으로 박는 게 더 적절. `Button` / `SelectTrigger` / `DialogClose` / `Label` 4종에 적용. CLAUDE.md / react-coding-conventions 의 cursor-pointer 룰에 예외 명시.

### 다크 border — `#1f2937` vs `#1e293b` vs `#334155`

| 방향        | 장점               | 단점                  |
| ----------- | ------------------ | --------------------- |
| `#1f2937`   | 기존, 매우 차분    | universal selector 적용 후 사실상 안 보임 |
| **`#1e293b`** ✅ | 차분 + surface(`#111827`) 보다 살짝 밝아 구분 가능 | -                     |
| `#334155`   | 분명히 보임        | 사용자 피드백 — 너무 밝음 |

→ universal selector 도입 전엔 border 가 `currentColor`(흰색) 으로 노출되던 게 문제였지 색 자체가 문제가 아니었음. 토큰 강제 후엔 `#1e293b` 로도 충분히 차분하면서 시각적 구분 보존.

### 도넛 가운데 텍스트 — Recharts label vs overlay div

| 방향                            | 장점               | 단점                                          |
| ------------------------------- | ------------------ | --------------------------------------------- |
| Recharts `Pie` `label` prop     | SVG 내부 통합       | slice 애니메이션 종료 후에야 텍스트 렌더 (~1.5초 지연) |
| **상위 `relative` div + 절대위치 overlay** ✅ | 즉시 렌더, 한 번만 그림 | -                                             |

→ Pie `label` 콜백은 데이터 포인트마다 호출되어 동일 텍스트가 N 번 그려지고, 슬라이스 애니메이션이 끝나야 보이는 한계. overlay 가 단순/즉시.

### 모바일 모달 액션 버튼 — sticky vs static 풀폭

| 방향                              | 장점                  | 단점                                    |
| --------------------------------- | --------------------- | --------------------------------------- |
| sticky bottom + border-t + bg     | 스크롤 중에도 항상 노출 | 모바일에서 시각적 분리감/덧붙은 느낌     |
| **static + flex flex-1 (풀폭 2열)** ✅ | 단순, 자연스러움       | 매우 긴 폼이면 스크롤 후 노출           |

→ 사용자가 "위로 올리지 마"로 명시. 폼이 짧아 sticky 까진 불필요.
