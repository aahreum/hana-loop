## 사용자 요청 흐름

1. **"#5 unit 미스매치가 뭐야? 내가 찾은거 맞아?"**
   → emission_factor.unit(`kgCO2e/kWh`) 와 activities.unit(`kWh`) 의미 차이 설명. ActivityForm 이 전자를 후자에 그대로 복사하는 버그. 사용자가 정확히 발견했음 확인 후 수정 시작.

2. **"#5 + #3 같이 먼저"**
   → ActivityForm 의 단위 input 영역 제거 + 활동량 라벨에 `(kWh)` 표시. factor 선택 시 `f.unit.split('/')[1]` 로 분모 추출. Zod max 추가 + 테스트 2건.

3. **"라이트모드 사이드바 라인 다크모드랑 동일하게. 드롭다운 외곽 라인도 빠져야"**
   → 이전 PR `border-white/5` 약화로는 라이트 본문 대비 여전히 두드러짐. 라인 자체를 모두 제거 + select 외곽 border 도 제거 (영역은 `bg-white/10` 으로만).

4. **"삭제할 때 블러 처리 어색. 낙관적 업데이트로 바꾸자"**
   → 이전에 README trade-off 로 명시했던 "Optimistic Update 미채택" 정책을 전환. `useDeleteActivity` 에 `onMutate` 낙관적 제거 + `onError` 캐시 스냅샷 롤백 + `onSettled` invalidate. activities + emission_results 양쪽 처리. `ActivityTableContainer` 의 `deletingId` 상태 / dim / disabled 모두 제거. README + docs/03 + docs/06 동기화.

5. **"잘되네 + 모바일에서 날짜 input 크기 각양각색"**
   → mobileInputClass 에 `text-sm` 명시. native picker 가 OS system font 영향받는 점도 안내.

6. **"바텀시트 하단 32px 마진 + 하단 rounded 빠져야"**
   → 처음엔 `bottom-8` 적용. 사용자가 "검은 반투명 영역이 어색" → 다시 `bottom-0` + `min-h-[300px]` 로 변경.

7. **"바텀시트가 viewport 폭이어야 하는데 396.5 만 됨"**
   → 414 - 17.5 = 396.5 정확히 일치. `scrollbar-gutter: stable` 이 모바일에서도 17.5px 예약하는 게 원인. `@media (min-width: 1024px)` 로 한정.

8. **"조회 기간 시트 상단 빈 영역 좁혀줘"**
   → 처음엔 `gap-3` + `mt-2` 제거로 시도. 사용자가 "DialogContent 가 grid 라 gap 안 먹는듯, flex 로 바꿔줘" → `AppDialogContent` 에 `flex flex-col` 강제. tailwind-merge 가 grid vs flex 충돌 처리해 flex 우선.

## 주요 결정 및 트레이드오프

### 1. 단위 필드 — 컬럼 제거 vs 폼 입력만 제거

| 방향                                | 장점                              | 단점                                |
| ----------------------------------- | --------------------------------- | ----------------------------------- |
| `activities.unit` 컬럼 자체 제거    | 가장 깨끗 (redundant 데이터 없음) | DB 마이그레이션 필요, seed 호환성 깨짐 |
| **폼에서 입력 제거 + 자동 도출** ✅ | 호환성 유지 + UI 단순화. seed 와 일관 | 컬럼은 redundant 하지만 유지       |

→ 마이그레이션 비용 회피. factor 선택 시 분모 자동 채움 + hidden input 으로 RHF 검증 보존.

### 2. 삭제 정책 — dim vs Optimistic Update

| 방향                              | 장점                            | 단점                                            |
| --------------------------------- | ------------------------------- | ----------------------------------------------- |
| 행 dim + invalidate (이전)         | 구현 단순. maybeFail 시 안전    | jitter 200~800ms 동안 흐려지는 게 어색          |
| **Optimistic Update + 롤백** ✅    | 클릭 즉시 반응. KPI/차트도 즉시 갱신 | 캐시 스냅샷 + 양쪽 캐시 처리 — 코드 복잡도 ↑ |

→ 사용자 직접 사용 후 어색함 보고. README trade-off 표 의 이전 결정 자체를 갱신.

### 3. 사이드바 라인 — alpha 약화 vs 완전 제거

| 방향                       | 장점                              | 단점                              |
| -------------------------- | --------------------------------- | --------------------------------- |
| `border-white/5` (이전)    | 아주 약하게 영역 구분             | 라이트 모드에서는 여전히 도드라짐 |
| **완전 제거** ✅            | 라이트/다크 시각 완전 통일        | 영역 구분이 spacing 만 남음       |

→ 라이트 모드에서 어떤 흰 alpha 도 본문 대비로 도드라짐. spacing 으로만 충분.

### 4. 바텀시트 — `bottom-8` 떠있게 vs `bottom-0` 붙이기

| 방향                                | 장점                              | 단점                                            |
| ----------------------------------- | --------------------------------- | ----------------------------------------------- |
| `bottom-8` (떠있는 형태)             | 부유 시트 디자인                  | 빈 32px 영역에 dialog overlay 검정이 보여 어색 |
| **`bottom-0` + `min-h-[300px]`** ✅ | 화면 하단 붙어 일관, 충분한 높이   | 부유 효과 없음                                  |

→ 사용자 시각 확인 후 검은 overlay 영역 제거 의도.

### 5. `scrollbar-gutter: stable` 적용 범위

| 방향                              | 장점                              | 단점                                |
| --------------------------------- | --------------------------------- | ----------------------------------- |
| 전체 적용 (이전)                   | 데스크탑 layout shift 방지         | 모바일에서 17.5px viewport 손실     |
| **`@media (min-width: 1024px)`** ✅ | 데스크탑 보호 + 모바일 손실 회피  | 미디어 쿼리 분기 추가              |

→ iPhone 14 414px → 396.5px 손실이 바텀시트 width 와 직결되어 명확히 드러남. lg 한정 적용으로 양쪽 만족.

### 6. `AppDialogContent` layout — grid vs flex

| 방향                            | 장점                              | 단점                                            |
| ------------------------------- | --------------------------------- | ----------------------------------------------- |
| shadcn default `grid` 유지      | 변경 없음                         | gap 적용이 grid context 라 호출부에서 직관적이지 않음 |
| **wrapper 에서 `flex flex-col` 강제** ✅ | 모든 다이얼로그에 일관 적용. gap-3 등 호출부 제어 명확 | tailwind-merge 의존 (grid vs flex 충돌 처리)   |

→ 모든 호출부가 child 를 column 으로만 배치하므로 flex 가 자연스러움.
