## 주요 결정 및 트레이드오프

### 원격 DB 적용 방법

| 방향                        | 장점                           | 단점                       |
| --------------------------- | ------------------------------ | -------------------------- |
| **Supabase SQL Editor 직접 실행** ✅ | CLI 연결 불필요, 즉시 실행, 가장 단순 | 변경 이력 추적은 별도 마이그레이션 파일에만 |
| Supabase CLI (`db push`)    | 표준 워크플로우                | `supabase link` 필요, 부가 설정 |

→ 과제 환경에선 SQL Editor가 가장 빠르고 단순. 마이그레이션 파일은 레포에 기록용으로 별도 추가.

### initial_schema.sql 처리

| 방향                                | 장점                                  | 단점                       |
| ----------------------------------- | ------------------------------------- | -------------------------- |
| 원복(5 enum) + 새 마이그레이션      | 변경 이력이 깔끔                      | initial을 두 번 수정       |
| **현재(3 enum) 유지 + 새 마이그레이션** ✅ | 추가 수정 없음, 사용자 선호           | db reset 시 새 마이그레이션 NOOP |

→ 사용자 결정. db reset 시에도 새 마이그레이션의 DROP TYPE/RENAME은 idempotent하게 동작.

### enum 교체 시 RPC 함수 처리

| 방향                              | 장점                          | 단점                                  |
| --------------------------------- | ----------------------------- | ------------------------------------- |
| `DROP TYPE ... CASCADE`           | 한 줄로 끝남                  | RPC 함수가 조용히 사라짐 (위험)       |
| **명시적 DROP FUNCTION + 재생성** ✅ | 함수 정의 보존, 의도 명시적   | SQL 길어짐                            |

→ 과제용이지만 production 마인드셋. 함수 사라지면 활동 추가 기능이 망가짐.

### source 라벨 정합성 처리

| 방향                                | 장점                  | 단점                                  |
| ----------------------------------- | --------------------- | ------------------------------------- |
| `UPDATE emission_factors SET source = '...'` | 데이터 보존           | activities/results 등 다른 잔재 그대로 |
| **TRUNCATE + seed.sql 재실행** ✅   | 완전 초기화, seed.sql과 100% 일치 | activities 데이터 재시드 필요        |

→ 사용자가 원격에서도 깔끔한 시드 상태를 원함. TRUNCATE...CASCADE + INSERT 순서 + emission_results 자동 계산 SELECT 한 트랜잭션으로 처리.

### 테이블 카드뷰 분기점

| 방향                  | 장점                    | 단점                                   |
| --------------------- | ----------------------- | -------------------------------------- |
| md (768px)            | 데스크탑에서 더 빨리 표 | 태블릿에서 8컬럼 표 문자별 줄바꿈 발생 |
| **lg (1024px)** ✅    | 태블릿까지 카드뷰 안전  | 작은 노트북(13인치 미만)도 카드        |

→ 태블릿/모바일 가독성 우선. 세 표(activities, factors, recent activities) 모두 lg로 통일하고 companies 카드뷰도 같은 분기점.

### h2/h3/h4 반응형 사이즈

| 태그 | 모바일                     | lg 이상                 |
| ---- | -------------------------- | ----------------------- |
| h2   | `text-base` (16px)         | `text-lg` (18px)        |
| h3   | `text-sm` (14px)           | `text-base` (16px)      |
| h4   | `text-base` (16px)         | `text-lg` (18px)        |

→ 모바일에서 헤더가 본문보다 너무 크지 않게. lg 이상은 기존 위계 유지.

## 오류 수정 이력

### Supabase 마이그레이션 실행 시

| 오류                                                                 | 원인                                                  | 수정                                                                  |
| -------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------- |
| `cannot drop type activity_type_enum because other objects depend on it` | `create_activity_with_emission` RPC가 enum을 시그니처에 사용 | DROP TYPE 전에 `DROP FUNCTION IF EXISTS create_activity_with_emission(...)` 추가 → enum 교체 후 동일 정의로 `CREATE OR REPLACE FUNCTION` 재생성 |
| `duplicate key value violates unique constraint "companies_pkey"`    | seed.sql만 실행하고 TRUNCATE를 빠뜨림 (UUID 하드코딩) | `BEGIN; TRUNCATE ... CASCADE; INSERT ...; COMMIT;` 한 트랜잭션 통합 SQL 재제공 |
