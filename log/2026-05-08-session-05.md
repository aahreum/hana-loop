## 주요 결정 및 트레이드오프

### 다크모드 구현 방식 — Tailwind `dark:` vs CSS 변수

| 방향                          | 장점                                | 단점                                                   |
| ----------------------------- | ----------------------------------- | ------------------------------------------------------ |
| Tailwind `dark:` 모디파이어   | 컴포넌트마다 색이 보여 콜로케이션   | 색이 수백 군데 흩어짐, shadcn/Recharts와 시스템 혼재   |
| **CSS 변수 + `:root.dark`** ✅ | 토큰 단일 소스, 변경이 한 곳에 집중 | "지금 무슨 색이 다크에서 적용되는지" 컴포넌트에서 모름 |

→ 이 프로젝트는 Tailwind v4 CSS-first + shadcn/ui CSS 변수 + Recharts JS 색상값까지 한 시스템으로 묶여 있어서 `:root.dark` 방식이 우월. 현행 유지.

### 폰트 로딩 방식 — 3가지 비교

| 방향                      | 파일 크기        | preload | CLS    | 캐시 분리                      |
| ------------------------- | ---------------- | ------- | ------ | ------------------------------ |
| `@fontsource/pretendard`  | weight별 다중 파일 (~5MB)  | 수동    | 수동   | ✅                              |
| **`next/font/local`** ✅  | variable 단일 파일 (~2MB) | 자동    | 자동 0 | ✅                              |
| Data-URI in CSS           | base64 +33%       | 불가    | 불가   | ❌ (CSS 변경 시 폰트도 재다운) |

→ next/font/local 채택. variable 폰트 한 개로 weight 전부 커버 + 빌드 타임 메트릭 분석으로 CLS 자동 보정.

### weight 범위 선언 — 표준 vs 실제 스펙

| 방향                    | 장점                               | 단점                                |
| ----------------------- | ---------------------------------- | ----------------------------------- |
| `weight: '100 900'`     | CSS 표준 친숙                      | 폰트 실제 지원 범위(45~930) 미반영  |
| **`weight: '45 930'`** ✅ | 폰트 파일 실제 axis 그대로 선언    | 표준 범위 아님                      |

→ 사용자 요청으로 실제 스펙 채택. 빌드 타임 검증용 정보일 뿐 런타임 결과는 동일.
