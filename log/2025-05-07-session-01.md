## 주요 결정 및 트레이드오프

### `activities.date` vs `yearMonth`

| 방향                                   | 장점                                                           | 단점                                      |
| -------------------------------------- | -------------------------------------------------------------- | ----------------------------------------- |
| `yearMonth` (기존)                     | 단순, 조회 빠름                                                | Excel 원본 날짜 손실, 추후 일별 분석 불가 |
| **`date` + generated `year_month`** ✅ | Excel 원본 보존, 일별 분석 가능, Excel 직접 임포트 보너스 대응 | 컬럼 추가, 마이그레이션 복잡도 소폭 증가  |

→ **`date` 선택.** 과제 보너스 조건(Excel 직접 임포트 인터페이스) 대응을 위해.

### `factor_category` 위치

| 방향                                     | 장점                             | 단점                                       |
| ---------------------------------------- | -------------------------------- | ------------------------------------------ |
| API에서 type+description으로 자동 매핑   | activities 단순                  | 매핑 규칙 변경 시 과거 결과 달라질 수 있음 |
| **`activities.factor_category` 명시** ✅ | 어떤 계수를 썼는지 불변으로 기록 | 활동 생성 시 factor 선택 UI 필요           |

→ **명시 선택.** activities는 불변(immutable) 원칙. 어떤 배출계수로 계산했는지 추적 가능해야 함.

### 가짜 백엔드 위치

| 방향                                        | 장점                                   | 단점                            |
| ------------------------------------------- | -------------------------------------- | ------------------------------- |
| 별도 `fakeApi.ts` 인메모리 서버             | spec 예시와 동일                       | Supabase와 이중 구현, 코드 중복 |
| **Next.js API Route + jitter/maybeFail** ✅ | Supabase 실제 데이터 사용, 코드 단일화 | spec 예시와 구조 다름           |

→ **API Route 선택.** 실제 Supabase에 연결하되 네트워크 시뮬레이션만 API Route 레이어에서 적용. 과제 의도(loading/error/rollback 테스트)를 만족하면서 실제 DB도 사용.

## 추가 작업 (세션 후반)

### SQL 오류 수정

| 오류                                                 | 원인                                                       | 수정                                                                  |
| ---------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------- |
| `generation expression is not immutable`             | `to_char`, `LEFT(date::text)` 모두 STABLE — DateStyle 의존 | Generated column → BEFORE INSERT trigger (`fn_set_year_month`)로 교체 |
| `invalid input syntax for type uuid: "p0000000-..."` | `p`는 16진수가 아님 (UUID는 0-9, a-f만 허용)               | `p0000000` → `b0000000` (seed.sql, data/seed.ts 동시)                 |
